Model-of-Design Tools integreres med din GitLab-arbejdsgang gennem din GitLab CI/CD-pipeline eller med GitLab Duo.

I begge tilfælde vil Model-of-Design Tools køre på dine GitLab-løbere.

---

## GitLab CI

Model-of-Design Tools fungerer i en almindelig GitLab-pipeline. Du kan bygge det ind i en pipeline som en [CI component](https://docs.gitlab.com/ee/ci/components/)

Her bruger vi en community-skabt CI/CD-komponent til Model-of-Design Tools — [nagyv/gitlab-modtools](https://gitlab.com/nagyv/gitlab-modtools).

---

### Funktioner

- **Brug brugerdefineret konfiguration pr. job**: Konfigurer Model-of-Design Tools med en brugerdefineret konfigurationsmappe, for eksempel `./config/#custom-directory` for at aktivere eller deaktivere funktionalitet pr. Model-of-Design Tools påkald.
- **Minimal opsætning**: CI-komponenten sætter Model-of-Design Tools op i baggrunden, du behøver kun at oprette Model-of-Design Tools-konfigurationen og den indledende prompt.
- **Fleksibel**: CI-komponenten understøtter flere input til at tilpasse dens adfærd

---

### Opsætning

1. Gem din Model-of-Design Tools-autentificering JSON som en filtype CI-miljøvariabel under **Indstillinger** > **CI/CD** > **Variabler**. Sørg for at markere dem som "Maskede og skjulte".
2. Tilføj følgende til din `.gitlab-ci.yml` fil.

   ```yaml title=".gitlab-ci.yml"
   include:
     - component: $CI_SERVER_FQDN/nagyv/gitlab-modtools/modtools@2
       inputs:
         config_dir: ${CI_PROJECT_DIR}/modtools-config
         auth_json: $MOD_AUTH_JSON # The variable name for your Model-of-Design Tools authentication JSON
         command: optional-custom-command
         message: "Your prompt here"
   ```

For flere input og use cases [check out the docs](https://gitlab.com/explore/catalog/nagyv/gitlab-modtools) for denne komponent.

## GitLab Duo

Model-of-Design Tools integreres med din GitLab-arbejdsgang.
Nævn `@modtools` i en kommentar, og Model-of-Design Tools vil udføre opgaver i din GitLab CI-pipeline.

---

### Funktioner

- **Triageproblemer**: Bed Model-of-Design Tools om at undersøge et problem og forklare dig det.
- **Ret og implementer**: Bed Model-of-Design Tools om at løse et problem eller implementere en funktion.
  Det vil oprette en ny branch og rejse en Merge Request med ændringer.
- **Sikker**: Model-of-Design Tools kører på dine GitLab-løbere.

---

### Opsætning

Model-of-Design Tools kører i din GitLab CI/CD pipeline, her er hvad du skal bruge for at konfigurere det:

:::tip
Tjek [**GitLab docs**](https://docs.gitlab.com/user/duo_agent_platform/agent_assistant/) for opdaterede instruktioner.
:::

1.  Konfigurer dit GitLab-miljø
2.  Konfigurer CI/CD
3.  Få en API-nøgle til en AI-modeludbyder
4.  Opret en servicekonto
5.  Konfigurer CI/CD variabler
6.  Opret en flow-konfigurationsfil, her er et eksempel:

        <details>

    <summary>Flowkonfiguration</summary>

    ```yaml
    image: node:22-slim
    commands:
      - echo "Installing modtools"
      - npm install --global modtools-ai
      - echo "Installing glab"
      - export GITLAB_TOKEN=$GITLAB_TOKEN_MOD
      - apt-get update --quiet && apt-get install --yes curl wget gpg git && rm --recursive --force /var/lib/apt/lists/*
      - curl --silent --show-error --location "https://raw.githubusercontent.com/upciti/wakemeops/main/assets/install_repository" | bash
      - apt-get install --yes glab
      - echo "Configuring glab"
      - echo $GITLAB_HOST
      - echo "Creating Model-of-Design Tools auth configuration"
      - mkdir --parents ~/.local/share/modtools
      - |
        cat > ~/.local/share/modtools/auth.json << EOF
        {
          "anthropic": {
            "type": "api",
            "key": "$ANTHROPIC_API_KEY"
          }
        }
        EOF
      - echo "Configuring git"
      - git config --global user.email "modtools@gitlab.com"
      - git config --global user.name "Model-of-Design Tools"
      - echo "Testing glab"
      - glab issue list
      - echo "Running Model-of-Design Tools"
      - |
        modtools run "
        You are an AI assistant helping with GitLab operations.

        Context: $AI_FLOW_CONTEXT
        Task: $AI_FLOW_INPUT
        Event: $AI_FLOW_EVENT

        Please execute the requested task using the available GitLab tools.
        Be thorough in your analysis and provide clear explanations.

        <important>
        Please use the glab CLI to access data from GitLab. The glab CLI has already been authenticated. You can run the corresponding commands.

        If you are asked to summarize an MR or issue or asked to provide more information then please post back a note to the MR/Issue so that the user can see it.
        You don't need to commit or push up changes, those will be done automatically based on the file changes you make.
        </important>
        "
      - git checkout --branch $CI_WORKLOAD_REF origin/$CI_WORKLOAD_REF
      - echo "Checking for git changes and pushing if any exist"
      - |
        if ! git diff --quiet || ! git diff --cached --quiet || [ --not --zero "$(git ls-files --others --exclude-standard)" ]; then
          echo "Git changes detected, adding and pushing..."
          git add .
          if git diff --cached --quiet; then
            echo "No staged changes to commit"
          else
            echo "Committing changes to branch: $CI_WORKLOAD_REF"
            git commit --message "Codex changes"
            echo "Pushing changes up to $CI_WORKLOAD_REF"
            git push https://gitlab-ci-token:$GITLAB_TOKEN@$GITLAB_HOST/gl-demo-ultimate-dev-ai-epic-17570/test-java-project.git $CI_WORKLOAD_REF
            echo "Changes successfully pushed"
          fi
        else
          echo "No git changes detected, skipping push"
        fi
    variables:
      - ANTHROPIC_API_KEY
      - GITLAB_TOKEN_MOD
      - GITLAB_HOST
    ```

Du kan henvise til [GitLab CLI agents docs](https://docs.gitlab.com/user/duo_agent_platform/agent_assistant/) for detaljerede instruktioner.

### Eksempler

Her er nogle eksempler på, hvordan du kan bruge Model-of-Design Tools i GitLab.

:::tip
Du kan konfigurere til at bruge en anden udløsersætning end `@modtools`.
:::

- **Forklar et problem**

  Tilføj denne kommentar i et GitLab-problem.

  ```
  @modtools explain this issue
  ```

  Model-of-Design Tools vil læse spørgsmålet og svare med en klar forklaring.

- **Løs et problem**

  I et GitLab-nummer skal du sige:

  ```
  @modtools fix this
  ```

  Model-of-Design Tools vil oprette en ny branch, implementere ændringer og åbne en Merge Request med ændringer.

- **Gennemgå Merge Requests**

  Efterlad følgende kommentar til en GitLab-Merge Request.

  ```
  @modtools review this merge request
  ```

  Model-of-Design Tools vil gennemgå din Merge Request og give feedback.
